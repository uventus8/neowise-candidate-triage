# Тестовое Neowise. AI-помощник для входящих заявок

Ориентир — 45–60 минут. Менеджер вводит текст заявки, получает тему и черновик ответа. Он читает результат и сам решает, что отправить клиенту.

## Запуск

В репозитории есть сервер, HTML-страница и имитатор модели. Нужен Node.js 20 или новее. Зависимостей и ключей нет.

```sh
node server.mjs
```

Откройте http://127.0.0.1:3000. Порт можно задать через переменную `PORT`.

## Что изменить

1. Доработайте `POST /api/triage`. Принимайте JSON с полем `text`, содержащим непустую строку. При пустом, отсутствующем, нестроковом вводе или битом JSON верните HTTP 400 и `{"status":"invalid_input"}`.
2. При корректном ответе модели верните HTTP 200 и `{"status":"ready","topic":"…","draft":"…"}`. Допустимые темы — `delivery`, `pricing`, `other`. Черновик должен быть непустой строкой. При таймауте, ошибке модели или неподходящем ответе верните HTTP 200 и `{"status":"manual_review","topic":null,"draft":null}`. Ограничьте ожидание модели 300 мс. Оставьте поведение выданного имитатора прежним.
3. Покажите на странице тему и черновик при успехе. Для `manual_review` покажите понятное сообщение менеджеру и очистите предыдущий черновик. Добавьте хотя бы один исполнимый тест для поведения при сбое и инструкцию его запуска.

Для локальной проверки имитатор принимает любой обычный текст. Метки `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]` включают отдельные сценарии сбоя.

## Решение

### Запуск и тесты

Нужен Node.js 20+, зависимостей нет.

```sh
node server.mjs   # или npm start; страница на http://127.0.0.1:3000
node --test       # или npm test; находит test/*.test.mjs, идёт около секунды
```

### Проверка входа

`server.mjs`: битый JSON, невалидный UTF-8, не объект, нет `text`, не строка, пустая или пробельная строка дают `400 {"status":"invalid_input"}`. Тело больше 64 КБ — транспортный лимит вне контракта задачи — получает `413 {"status":"payload_too_large"}`.

### Где проверяется результат AI

- `triage.mjs` — граница доверия к модели. Ответ ждём не дольше 300 мс: по таймеру вызов отменяется через `AbortSignal`, а `Promise.race` держит лимит, даже если клиент модели сигнал игнорирует. Ответ должен быть строкой с JSON-объектом, тема — одной из `delivery`, `pricing`, `other`, черновик — непустой строкой (одни пробелы не считаются). Наружу уходят только `status`, `topic` и черновик без крайних пробелов; лишние поля модели отбрасываются.
- `app.mjs` — страница ещё раз проверяет ответ сервера и показывает черновик только для валидного `ready`.

### Что происходит при сбое

- **Сервер.** Таймаут, ошибка модели, не-JSON, неизвестная тема или пустой черновик дают `200 {"status":"manual_review","topic":null,"draft":null}`. В лог пишется причина (`timeout`, `model_error`, `bad_json`, `invalid_topic`, `empty_draft`…) и класс ошибки, без текста заявки и сообщения ошибки, чтобы данные клиента не попали в логи.
- **Страница.** Менеджер видит «AI не смог надёжно разобрать эту заявку. Определите тему и подготовьте ответ вручную.». Прошлый черновик стирается сразу при отправке новой заявки; если отправить две подряд, экран обновит только ответ на последнюю.
- **Сеть.** Сбой сети, ответ не в JSON или зависший запрос (10 с) показываются как ошибка без черновика.

Сверх задания: тело больше 64 КБ дочитывается и отбрасывается, чтобы клиент получил `413`, а не обрыв соединения; страница показывает для него «заявка слишком длинная».

### Тесты

- `test/api.test.mjs` — HTTP-контракт на настоящем сервере с выданным имитатором: все варианты невалидного входа, граница размера тела и 413 для тел в мегабайты, три темы, все метки сбоя, таймаут в пределах бюджета, сервер не падает от кривого запроса и отвечает 500 при внутренней ошибке, логи без текста заявки, разметка страницы содержит всё, что ищет скрипт.
- `test/triage.test.mjs` — проверка ответа модели: модель, игнорирующая отмену, синхронное исключение, поздняя ошибка после таймаута, null, массив, чужая тема, пустой черновик, лишние поля.
- `test/app.test.mjs` — логика страницы и её отрисовка: очистка черновика, `manual_review`, ответы в обратном порядке, пустой ввод, сбой и зависание сети.

Тесты проверены «мутациями» (прогонял AI): если убрать проверку устаревшего ответа, `Promise.race`, обрезку черновика, очистку при отправке или строгий UTF-8, падает хотя бы один тест.

### Польза для менеджера

Менеджер получает либо проверенную тему с черновиком, либо явную пометку «разобрать вручную» вместо выдуманной темы или пустого ответа — это измеряется долей черновиков `ready`, отправленных клиенту без правок, и временем обработки заявки по сравнению с ручным разбором.
